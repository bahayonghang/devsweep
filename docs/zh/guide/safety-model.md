# 安全模型

DevSweep 将发现、计划、验证和副作用分开处理。这是产品边界，而不是便捷功能。

## 先扫描

`scan` 会识别符合条件的项目产物和受支持的全局提供方。它在版本化报告中记录证据、
风险级别、清理意图、大小信息和健康诊断。扫描不会执行清理操作。

## 将保存的文档视为不可信输入

`clean --plan PATH` 会解析已保存的计划或扫描报告，验证其版本和结构，并依据
DevSweep 受信任的规则目录重建可执行操作。序列化计划不能选择任意程序或 shell
命令。详见[计划与报告](/zh/reference/plan-and-report)。

## 默认是演练执行

不带 `--execute` 时，`clean` 只会报告选中的目标数量，不会运行清理命令，也不会把
路径移入回收站。请利用该步骤确认保存的计划仍符合目标范围。

## 执行必须明确请求

执行同时需要计划路径和 `--execute`。项目产物通常通过回收站清理；Rust `target/`
则在适用 manifest 下使用 `cargo clean`。基于命令的全局清理会保持程序名与 argv
分离，不会拼接 shell 命令字符串。

请求执行时，DevSweep 会在副作用发生前重新检查已选目标和授权范围。它可以把 JSONL
审计记录追加到 `--audit-log` 指定路径；未指定时默认写入 `devsweep-audit.jsonl`。

## 明确的非目标

- 此构建中永久删除已禁用，且没有对应 CLI 选项。
- Docker 清理尚未实现，不会被扫描或执行。
- Cargo home 仅供检查。凭据、已安装二进制、registry 内部文件和 Git 缓存内部文件
  永远不会成为清理操作。
- 符号链接目录和 Windows reparse point 受到保护，不会作为清理目标被跟随。

## 保护自己拥有的路径

使用[`protect`](/zh/guide/protection)把现有路径加入持久保护列表。保护列表读取失败时
会拒绝继续，而不会静默退化为空列表。
