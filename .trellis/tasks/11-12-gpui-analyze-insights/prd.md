# Analyze：大文件、多选与分栏树图

父任务：[11-12-gpui-mole-parity-airy-glass](../11-12-gpui-mole-parity-airy-glass/prd.md)。差距编号 A1–A4 见父任务 `research/gap-analysis.md`。

## 目标

在 Analyze 里同时看到当前目录的列表和树图，能直接找到最大的文件，能一次选多个节点生成一份回收站计划。大文件列表和卷容量先在 core 和 CLI 提供。

## 需求

| 编号 | 层 | 需求 | 差距 |
| --- | --- | --- | --- |
| R1 | core、CLI | `analyze largest --snapshot FILE [--min-bytes N] [--limit N]`：从已有快照里列出最大的文件，有界，顺序稳定。只覆盖快照里保留的文件节点，并在输出里说明这一限制。 | A1 |
| R2 | core、CLI | `analyze roots` 的每个位置带卷总量和可用量证据；拿不到时说明原因。 | A3 |
| R3 | GPUI | 详情页分栏：左列表，右树图；窄窗口上下堆叠。 | A2 |
| R4 | GPUI | 多选节点，生成一份回收站计划，再走预览摘要和确认。 | A4 |
| R5 | GPUI | 行与树图单元的上下文菜单：在资源管理器中显示、加入回收站计划、解释。键盘可达。 | A4 |
| R6 | GPUI | "最大文件"分段，使用 R1 的结果。 | A1 |
| R7 | GPUI | 位置卡显示大写盘符和容量条。 | A3 |
| R8 | GPUI | 中文界面下 Analyze 的错误提示用中文（当前由 `shell.rs` 原样透出英文）。来自 airy-glass-shell 评审遗留。 | S9 |

## 验收

- AC1（R1）：CLI 契约测试覆盖 `analyze largest` 的 JSON 与人类可读输出、阈值、上限、相同容量时的稳定顺序、空结果。
- AC2（R1）：快照因遍历上限而不完整时，输出明确写出"仅限快照中保留的文件"。
- AC3（R2）：`analyze roots` 的容量字段有可用和不可用两种测试。
- AC4（R3）：宽窗口并排，窄窗口堆叠，各一张截图；列表选中项与树图高亮一致。
- AC5（R4）：选三个节点后生成的计划恰好含这三个节点；改动选择后旧摘要失效；没有摘要不能执行。
- AC6（R5）：上下文菜单可用鼠标右键和键盘菜单键打开，Escape 关闭，焦点回到原行。
- AC7：`just ci` 与 `just gpui` 通过。
