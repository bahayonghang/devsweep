# Status：CLI/core 指标补全与实时仪表盘

父任务：[11-12-gpui-mole-parity-airy-glass](../11-12-gpui-mole-parity-airy-glass/prd.md)。差距编号 T1–T4 见父任务 `research/gap-analysis.md`。

## 目标

切到 Status 就能看到这台机器现在的状态和最近一分钟的走势，不用先点按钮。缺少的指标先在 core 和 CLI 补上，桌面端再呈现。全程只读。

## 需求

| 编号 | 层 | 需求 | 差距 |
| --- | --- | --- | --- |
| R1 | core | 状态快照增加只读证据：机器身份（CPU 型号、系统版本、开机时间）、CPU 当前频率、提交内存与上限、GPU 适配器名称、电池健康度与循环次数与充放电功率、系统级磁盘读写速率、网络接口类型。每一项要么有值，要么说明为什么没有，绝不用 0 代替。 | T3 |
| R2 | CLI | `status snapshot --format json` 和 `status live` 的 NDJSON 带上新字段；人类可读输出补中英文两种文案。 | T3 |
| R3 | GPUI | Status 标签可见时自动开始实时采样，切走即停。保留暂停与继续。 | T1 |
| R4 | GPUI | 保留最近 60 个样本，给 CPU、GPU、内存、网络、磁盘活动画趋势。趋势只在新样本到达时重绘。 | T2 |
| R5 | GPUI | 指标格：健康证据（含机器身份标签）、CPU、GPU、内存、电源、可用空间、网络、磁盘活动。每格一个大数字、一条趋势或条形、一行说明。传感器缺失时显示原因。 | T3、T4 |
| R6 | GPUI | 进程表保留搜索、排序和行内解释，列为名称、内存、CPU、PID、磁盘读写。 | — |
| R7 | — | 不引入健康分数。健康格显示 `explain_health` 的证据结论。 | T4 |

## 验收

- AC1（R1）：core 测试覆盖每个新字段的"有值""不可用及原因"两种情形。采样仍在现有的时间预算内，不新增常驻线程。
- AC2（R2）：`cli_contract.rs` 与 `five_mode_contract.rs` 通过。JSON 输出的新字段有契约测试；旧字段的名称和含义不变。
- AC3（R2）：Tauri 桌面的封闭解码器（`desktop/src/api/contract.ts`）和夹具同步更新，`desktop` 的测试通过。
- AC4（R3）：进入 Status 后不点击任何按钮，两秒内出现读数。切到其他标签后，订阅停止计数加一，没有后续样本到达。
- AC5（R4）：连续运行两分钟，每条趋势恰好保留 60 个样本；暂停期间不追加。
- AC6（R5）：在没有电池、没有温度传感器的机器上，对应格子显示原因文字，没有 0% 或空白。
- AC7：空闲 3 秒内，Status 页面在非实时状态下的进程 CPU 时间与改动前处于同一量级（沿用 11-04 验收的测法）。实时状态下记录采样开销，不设硬门限。
- AC8：`just ci` 与 `just gpui` 通过。英文和中文各一组原生截图。

## 不在范围

结束进程和保持唤醒（属于 host-actions）。风扇转速与控制。按进程的能耗。托盘面板（属于 tray-panel）。健康分数。
