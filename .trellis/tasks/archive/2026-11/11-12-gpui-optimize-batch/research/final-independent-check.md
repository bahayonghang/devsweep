# R8 独立复核

2026-11-20，在 Windows 集成工作树使用临时审计目录和测试适配器。执行路径仅派发给夹具。原生窗口与两种语言的结果见[窗口记录](../evidence/native/acceptance.md)。

## 修正与复验

| 问题 | 复验 |
| --- | --- |
| V2 对失效启动项沿用单项的名称绑定。同名快捷方式变更目标时，旧的批次确认仍派发一次。 | V2 在旧单项摘要之上绑定每项删除类型、目标、链接路径和备份内容。预览后变更目标，整份旧摘要被拒；批内变更，当前项标记身份已变更。两种情况下夹具派发次数均为零。红绿日志为 `dist/verify-1120/r8-startup-{red,green}.log`。 |
| 历史按批次 ID 查询返回了完整记录，却用首项 ID 和状态概括整批。旧 CLI 在英文原生样本返回九条记录和第一项 ID。 | 新审计存预期项数，批次详情使用所请求的批次 ID 和所有成员的时间范围，校验每项的审计顺序与终态，再汇总结果。已测纯成功、全取消、成功/跳过/失败混合、按单项查询、缺失最后一个成员、旧记录无项数。缺失项数或记录不足时标为未知和部分。日志为 `dist/verify-1120/r8-batch-history-{red,green}.log`。 |
| 界面上旧取消回调可能取消后续批次。运行时进入历史页，只能看到打开时的快照。 | 取消检查当前批次代次与页面，旧取消回调随后续三项混合测试验证。历史页在已启动的执行返回结果或错误后重读审计。该刷新分支已审阅并编译，原生历史验收核验落盘数据和 CLI 查询。 |

## 逐项验收

- **AC1、AC2**。复跑四个批量 core 测试。只接受互不重复的已登记 Execute 项；重排或删项使旧摘要无效；失去权限和身份变化逐项跳过；原先拒绝的项不会因权限变宽被临时纳入。按单项参数保存旧 V1、DNS 单项假执行、设置跳转 Launched、恢复不重派均通过。原 V1 计划与摘要格式保留；完整的同名启动项目标绑定属于新增 V2 批次。
- **AC3**。真实 CLI 参数契约与注入夹具的处理器各一项通过。反复传入的操作按顺序保存；无摘要或无确认拒绝执行；失败后继续并返回非零，结果仍含全部单项。
- **AC4**。独立解析四份原生默认设置记录，普通构建英文/中文、浅色/深色均为七个 Off、审阅禁用。七项 Execute 有复选框，八项指引与三个设置跳转位于折叠区，只读磁盘健康在状态栏。[默认值存档](../evidence/native/defaults.json)
- **AC5、AC6**。独立对照英文和中文各三项 UIA 行、历史列表、共享批次 ID、不同的三项执行 ID 和精确的成功数 1。三项顺序为时钟采样失败、SSD 整理因权限跳过、DNS 成功。未请求提权。运行中的取消只在下一项边界生效。隔离执行器将实时解析和派发均固定到内存适配器；无执行器的会话和 Clean 夹具不能派发维护。
- **中断审计**。损坏审计时未进入第一项，原审计字节不变；锁冲突、恢复不重派和总计冲突夹具分别通过。正常适配器错误继续，其前提是审计仍可写。没有在真实磁盘上制造空间耗尽。
- **AC7**。独立执行两工作区格式检查和桌面批次定向测试（2/2）。实现方修正旧单项键盘预期后，普通 GPUI 主程序 262 项通过、2 项忽略，画廊 4 项通过。最终完整 `just ci`、`just gpui` 以及新审计项数的原生复验由父任务统一记录。
