# Windows 验收记录

## 被测版本

- 仓库分支 `dev`，基线提交 `dc7cc8a`。原发布程序的 UIA 树暴露 Keep Screen On 和 Clean Screen。
- 本次构建通过 `just gpui-build` 生成。最终发布程序 SHA-256 为 `10A9EAA4823090192A3D8AFD304749CC296C4F597B74B4E3C9C5E19650408164`。
- 每种语言均使用新进程与独立临时配置目录。窗口消息只定向发送到该进程的 HWND，未运行扫描或电源命令。

## 验证结果

| 检查 | 观察结果 |
|---|---|
| 英文宽窗口，1370 逻辑像素，系统默认合成 | 鼠标点太阳后标题栏变为月亮，窗口中心像素亮度从 0.108 升至 0.718。焦点在主题按钮时按 Enter 切回深色。 |
| 中文紧凑窗口，790 逻辑像素，禁用 DirectComposition | 同一往返通过，中心像素亮度从 0.141 升至 0.941。截图确认设置图标为带中心孔的齿轮，与太阳、月亮均可区分。 |
| 设置入口与命中区域 | 鼠标、Tab 后 Enter 和 UI Automation Invoke 均可打开设置；连续 Invoke 停在同一页。主题、齿轮、最小化三个按钮的水平边界互不重叠。 |
| 草稿与返回 | UIA 切换主题后，设置页对应主题项成为选中项。点击标题栏不写入 V2 偏好文件。两种语言下，通过齿轮离开 Clean 的 AI 审查子页，再按 Escape，均回到该子页且笔记仍为 `note17`。 |
| 保留的键盘入口 | F10 菜单进入同一设置页。F11 显示清屏遮罩，Escape 恢复设置。普通控件和 Note 聚焦时按 F12，均未出现常亮横幅。 |

## 自动化与边界

- `just gpui-check`、`just gpui-test`（167 项）、`just gpui-build` 和根工作区 `just ci` 全部通过。
- 自动化覆盖全部已有主题的往返、显式保存与未保存的重启行为、全部五个模式的设置往返及清屏恢复。
- 本机原生验收时 Windows 系统高对比度关闭。高对比度配色优先级和基础主题往返由 Rust 测试覆盖，没有切换用户的系统设置。
