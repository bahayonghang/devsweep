# 实施与验证顺序

1. 建立针对两个真实入口的回归检查。记录当前 GPUI 标题栏 ID、F11/F12 上下文、设置页返回路径与偏好草稿的磁盘基线。使用临时 PreferenceFiles，避免改动用户配置。
2. 完成太阳／月亮的动作、中英文名称和资源注册，复用设置页的 Session 草稿与重绘。覆盖 Dark/Light 往返、兼容主题首次点击、高对比度下连续点击、先编辑其他字段再切主题、保存与未保存两条重启路径。
3. 接入齿轮和既有 Settings 页面，用同一导航路径覆盖菜单与标题栏。验证从各模式进入、重复进入、返回及 Note 保留。去掉 GPUI 常亮动作、键位与横幅。单独验证原 F12 在页面及输入框都无法触发租约，F11 与 Escape 能完成清屏和恢复。
4. 在仓库根目录运行 `just gpui-check`、`just gpui-test`、`just gpui-build`、`just ci`。需能通过按钮交互或动作分派复现目标结果，仅搜索源码字符串不足以验收。
5. 在 Windows GPUI 原生窗口，用鼠标、Tab/键盘激活和 UIA 操作两个控件。记录深→浅→深、齿轮→设置→返回、中文/英文标签、窄宽窗口及系统按钮命中。观察玻璃与实色回退，记录实际测试的高对比度条件。分别附自动化测试、原生结果和未验证项。

回退范围限于 GPUI 标题栏动作、旧入口清理和对应测试；沿用现有偏好格式，回退无需迁移用户数据。
