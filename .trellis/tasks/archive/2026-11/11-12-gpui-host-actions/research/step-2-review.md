# 步骤 2 评审决定（用户已确认）

2026-11-15。步骤 1 已由 `trellis-implement` 完成，[原始研究](msi.md)由 `trellis-check` [独立核对](msi-review.md)。用户已明确“按这四项继续步骤 3–8”，批准下列固定参数、结果规则、R11 与 AC7 边界；主代理据此同步 PRD/设计。原研究的绝对零 UAC 与 owner receipt 建议不属于已批准实现。

## 1. 固定命令与结果规则

程序由系统 API 解析为绝对路径，并绑定同一实际文件的身份与哈希。参数独立传递：

```text
program: <系统目录>/msiexec.exe
argv: ["/x", "{PRODUCT-CODE}", "/qn", "/norestart"]
```

产品代码按花括号 GUID 严格校验；不读取厂商卸载命令，不通过 shell，不自动提权、切换交互模式、重试或重启。参数依据见 [Microsoft 标准选项](https://learn.microsoft.com/en-us/windows/win32/msi/standard-installer-command-line-options)。

| 结果 | 建议的应用语义 |
| --- | --- |
| `0`，且精确 SID/context 的权威查询确认同一登记已消失 | 记为 `Removed`；仅这个新 MSI 成功终态可进入残留流程 |
| `0`，但仍登记或查询失败/冲突 | 保留仍存在或结果未知；不开放残留 |
| `3010` | 成功但需要重启；保留退出码，不立即开放残留 |
| `1641` | 成功且已触发重启；与“需要重启”区分，记录它违背重启抑制预期，不开放残留 |
| `1605/1614/1618/1603/1602/3011` 或其他非成功码 | 保留真实码与独立登记状态；登记消失不能把失败变成“本次卸载成功” |
| 超时、丢失退出状态、派发后取消或崩溃 | 结果未知，不声称已回滚，不靠消失补造成功记录，不自动重放卸载 |

`0/1641/3010` 的 Installer 成功分类来自 [Microsoft 退出码](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes)；只有 `0 + 精确消失` 获得残留权限是建议的更严格应用策略。实现时需要 MSI 独立分类与审计重放验证，保持现有 MSIX 历史语义不变。

## 2. R11 的提权保证范围

**推荐确认的产品边界：**DevSweep 不主动请求提权，不使用 `runas` 或提权回退；固定关闭 Installer 内部 UI。已知需管理员权限、机器级、托管、其他用户、多上下文以及身份/限制证据不完整的条目拒绝。只在正向资格契约满足后开放当前用户非托管 MSI，不把所有这类条目直接视为可执行。

**明确排除的承诺：**不声称已证明任意第三方 MSI 自定义动作都绝不产生外部 UI 或 UAC。`/qn` 的内部 UI 契约不能成为任意包行为的沙箱；相关依据和推断边界见 [MsiSetInternalUI](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msisetinternalui)与独立检查。

若要求包含任意自定义动作的绝对零 UAC 保证，现有证据不足以定义通用资格判定；这时 MSI 派发应继续延后，不能用全部拒绝的分支声称 R2/AC2 已完成。

## 3. AC7 的保持唤醒语义

**推荐明确修改 AC7 为：**

- 复用现有 CLI 的显式 endpoint/token/owner 协议，并提到 core；一个专用 owner 线程持有、刷新与清除 OS 请求，GPUI 在进程内调用，不派生 CLI。
- 应用仍在运行时，CLI 可查询指定 GUI 会话为 active/stopped；停止后保留可查询端点，只有清除成功才报告 stopped/off。
- GUI 退出释放自身请求并 join owner 线程。退出后的旧端点不可达时，CLI 如实报告 unavailable/unknown，不凭连接失败宣称 off。
- 不影响其他 CLI/GUI owner；获取或清除 OS 请求失败时如实报告，不能以本地表状态冒充成功。

本轮不新增生命周期收据或后台常驻服务。研究中的收据建议尚缺完整权限、身份、重启/PID 复用及读写时序契约；若必须保持“GUI 退出后 CLI 仍报告 off”的原 AC7，需要另行设计与评审，不能直接批准一个字段清单。
