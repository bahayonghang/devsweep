# 实施与验收顺序

1. [x] **建立基线（R1–R6）。** 在 Windows 同一显示器上记录构建提交、系统版本、DPI、窗口尺寸、文字缩放与夹具。以默认 1240×820、深浅两套相同 Clean 审阅场景为主对照，补一组窄窗；记录当前 Tab / UIA、窗口控制、列表滚动和空闲表现。
2. [ ] **先交付一个端到端切片（R1、R2、R5）。** 在 ui.rs 和 view.rs 接通底场、主面与实色回退，把顶栏和 Clean 审阅列表置于同一窗口。测试首次启动、已有主题重启、冷暖两端文字对比、高对比和系统关闭透明。对比原生效果开关截图。若失败，先修合成或记录技术阻塞，再扩到其余页面。
3. [x] **控件与状态（R2、R3）。** 迁移导航标签、分段按钮、普通／危险按钮、只读徽标、输入和选择行。复查 input.rs 的焦点和插入点。记录「选中 A、聚焦 B」、禁用、按下、忙碌和确认态；使用隔离夹具验证预览失效，实机演练停在确认或取消。
4. [x] **页面迁移（R3、R4）。** 检查 view/page_clean.rs、page_workbench.rs、page_analyze.rs、page_status.rs、page_support.rs 及 view.rs 的菜单与状态栏。逐项列出剩余硬编码表面色；复核 Clean 预览、Software 搜索、Optimize 风险提示、Analyze 图例、Status 刷新、设置和支持页。两种语言、文字放大和窄窗至少各有一个长内容样例。
5. [x] **运行门禁（R1–R6）。** 根目录运行 `just gpui-check`、`just gpui-test`、`just gpui-build`（也可合并为 `just gpui`）以及 `just ci`。覆盖主题选择和回退优先级、关键 token 对比、真实焦点及控件可操作性。运行成功后，以该版本 Windows 二进制核对 UIA 名称、角色、选中、Invoke、Tab 循环和标题栏最大化／还原。
6. [x] **视觉与性能复核（R4–R6）。** 在任务 evidence/ 记录同场景前后截图、对比度取样、窗口模式／回退原因和实机操作结果。同一 release 配置重复滚动与切页、比较帧时间和空闲 CPU；对可复现回退定位或改用实色并重测。人工检查嵌套玻璃、过度胶囊化、标签真假可点击、焦点与警告可辨性。design-atlas 静态检查需记录 Rust 的实际覆盖；无可检查文件不能计作通过。截图交独立复核或明确标注自检，给出通过／失败／未测清单。

前两步共用一套材质和焦点契约，后续逐页复用。无需为每个页面建立独立主题或子任务。

第 2 项的原生材质和实色回退已通过实测，Windows 全局高对比／透明度开关热切换仍待人工验收。详见 [Windows 验收记录](evidence/validation.md)。
