# Windows 原生验收

2026-11-04，本机 Windows build 26300，窗口 DPI 120（125%）。改动前从 `b7b5484` 构建，改动后使用当前工作树 release。完整二进制 SHA-256、尺寸及观测值见 [before.txt](before.txt) 和 [after.txt](after.txt)。

## 已验证

| 范围 | 方法和结果 |
| --- | --- |
| 原生材质 | 在应用窗口后放置蓝色、金色两个受控背景，确认采样点属于测试窗口。旧版两次采样相同。新版深浅主题在宽窗口均随背景变化；缩到 820 个逻辑像素以及以 `GPUI_DISABLE_DIRECT_COMPOSITION=1` 运行时，两次背景下的像素分别保持一致。截图用 PrintWindow，背景响应使用屏幕合成后的像素另行测量。 |
| 对比度 | 在宽窗口主面空白处取两种背景下的实测底色，用实际主题前景按 sRGB 相对亮度计算，取较低值。深色正文 12.98:1、次文 6.67:1、焦点 8.73:1、必要边界 5.05:1。浅色依次为 11.15:1、5.31:1、4.39:1、3.12:1。共享单元测试另覆盖实色内容区和高对比色板。 |
| 主题与布局 | 无主题存档时启动为深色。在设置中切到浅色，保存、关闭后用同一临时配置重启，UIA 读到 Light 选中。英语 100% 和中文 125% 各覆盖默认窗和窄窗；查看了五个主模式，并通过菜单访问设置、保护、规则、历史。 |
| 焦点和窗口 | 两种语言均验证选中 Clean 时聚焦 Software，Enter 切换到 Software，Tab 到 Optimize，再 Shift+Tab 返回。截图复核后将焦点改为内描边，解决透明标签被实心外阴影填满的问题。UIA Invoke 最大化、还原均成功。 |
| 安全确认 | 只扫描临时 Python 项目。生成预览前确认按钮禁用，选中一行并预览后，UIA 读取完整 sha256 摘要且确认可用。清空选择后确认再次禁用，样本文件仍在。没有调用执行。 |
| 滚动与空闲 | 同机同 release 配置、两条数据、每组 47 个 Present 间隔。深色 p95 从 32.04 ms 到 32.97 ms，浅色从 31.95 ms 到 32.08 ms。按 16 ms 休眠投递滚轮消息，数据包含驱动脚本的节拍，不能据此推断屏幕刷新率或大型列表性能。3 秒空闲进程 CPU 累计均在 0–16 ms 内。 |
| 项目门禁 | `just gpui` 通过格式、严格 Clippy、164 项 Windows GPUI 测试和 release 构建。根工作区 `just ci` 通过。 |
| Debug 回归 | 单独构建带调试断言的二进制，在开启 UIA 时依次向五个模式标签投递鼠标点击，再重复点击已选标签，窗口正常退出。见 [debug.txt](debug.txt)。 |

## 证据边界

- 使用隔离偏好目录和项目夹具。用户明确将 Windows 全局高对比与透明度热切换保留为人工验收，当前系统设置保持原样。回退决策有单元测试，窄窗与关闭 DirectComposition 均已实机验收。
- design-atlas 静态检查对 Rust GPUI 报告 `files: 0`，不作为通过证据。本次视觉评审为自检，非独立复核。历史任务的大样本性能、维护操作和安装包验收不在本次范围。

## 人工验收步骤

使用 `just gpui-dev` 打开窗口，保持宽度至少 960 个逻辑像素，记下 Windows 原有设置。

1. 在 Windows 设置中关闭透明效果并返回已打开的 DevSweep。预期纸面恢复实色，深浅选择、布局和焦点仍在原处。恢复透明效果后复核宽窗材质。
2. 在 Windows 辅助功能中启用对比度主题。预期工作台使用高对比实色，Tab 到另一模式时能同时分辨选中项和焦点，危险动作仍有可读文字。恢复测试前的 Windows 设置后，核对原应用主题。
