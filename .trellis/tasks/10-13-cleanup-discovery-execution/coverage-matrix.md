All rows need outcome accounting even when unavailable. Default selections remain subject to verified size, freshness, ownership and protection policy. New provider defaults below are conservative.

## Per-rule readiness checklist

Record a stable rule id, supported OS/tool version, trustworthy root resolver and override precedence, detection evidence, supported nesting, action footprint, size-confidence semantics, rebuild cost/risk, default-selection policy, active-owner policy, live drift checks, audit outcome, and localized user explanation. This belongs with the existing rule catalogue, not a second GUI-only catalogue or a generic untrusted plugin loader.

Every executable row must have a complete scan/report/plan/preview/fake-execute fixture and at least one retained-data negative fixture. A row intentionally inspect-only needs explicit reasons and a disabled-action test. Windows-native owner/process and path-shim behavior needs native evidence before that row is called complete.

When a source/ownership rule cannot be verified, report the precise unavailable/inspect-only reason and keep the task criterion open. Do not widen path permissions to make a fixture pass. A requested destructive-policy change would require a separately reviewed task.
