# GPUI redesign and background reads — 2026-11-03

Scope: user request to analyse the GPUI rewrite and continue it, with a
modern front end. Commits on `codex/gpui-desktop-rewrite`: `a2dbe16`,
`a8988fb`, `aa1786e`, `39c7e90`.

## What was wrong at `a1d85cb`

- The window painted session state as debug text lines (`phase=Landing`,
  `root:0 | / | ready`, `class=execute | privilege=…`); keyboard hints were body
  text; Status buttons appeared on every mode; content overflowed with no scroll.
- Software segments read only env-var fixture files, so the window never showed
  real installed software, updates or startup items.
- Status snapshots (500 ms sample) and Analyze walks (whole drives) ran on the UI
  thread.
- `just gpui-check` could not pass: 16 clippy warnings, unformatted core file.

## What changed

- `src/ui.rs` design system (dark / light / Windows high-contrast tokens, rem
  scaling, components) and 41 original packaged SVG icons.
- `src/view.rs` shell plus `src/view/page_*.rs` pages for all five modes and the
  four menu destinations. Controls call the existing `Session` actions only.
  Row accessible names stay the full row text. `panel_entries` is now a
  `cfg(test)` text projection.
- `Session` background jobs (opt-in by the window, generation-guarded):
  host Software reads, Status snapshot, cancellable Analyze walk. Window never
  calls uninstall, startup-write or update-install APIs (unit-test guard).
- Windows deps are target-scoped; opt-in `linux-preview` feature renders the
  window under Xvfb for review screenshots.

## Follow-up 2: launch crash and Software rows

- Launch crash (`46c790f`): `just gpui-dev` opened the window, hung and then
  exited 1. Cause: a main-thread stack overflow in the debug build. GPUI builds
  each frame's element tree on the main thread, and unoptimized builder
  chains used about 0.5–0.65 MiB of stack on Linux (measured with `ulimit -s`).
  With MSVC debug frames this exceeds the Windows default of 1 MiB. Release
  builds hid the overflow message because of `windows_subsystem = "windows"`.
  Fix: `build.rs` links Windows binaries with an 8 MiB main stack
  (`/STACK:8388608` on MSVC). Debug builds keep a console. A panic hook
  appends to `%TEMP%\devsweep-gpui-crash.log`. `cargo check -vv` for the
  MSVC target shows the link argument. The fix is unconfirmed on the user's
  Windows host until `just gpui-dev` is re-run.
- Sizes (`879788c`): install size column with its qualifier (`~ reported`,
  `measured`, `≥ partial`), Sort: size (largest first, unknown last), and a
  "visible of total" badge.
- Updates and Startup rows (`9d5ff60`): Updates rows read
  "installed → available · source" with an Update available badge. Startup
  rows show Enabled / Disabled / Unknown, a readable location, and who may
  change the entry (current user, needs admin, or protected). Fixture hive
  state comes from the read-only `plan_startup_hive` + `preview_startup_hive`
  pair. A refused entry stays Unknown. No toggle runs from these rows.
