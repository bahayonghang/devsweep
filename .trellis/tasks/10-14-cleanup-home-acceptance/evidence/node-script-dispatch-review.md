# Windows Node script dispatch review and repair

Date: 2026-10-14. Reviewer: `backend_contract_check` (`trellis-check`). Parent authorized the bounded production repair after the controlled path/environment investigation.

## Confirmed finding

`process/provider_dispatch.rs` canonicalized the supported npm/pnpm/Yarn entrypoint and passed `script.display()` directly as Node's first argument. On Windows that produces a verbatim path such as `\\?\C:\...\npm-cli.js`. Both global discovery (`scan/global/probe.rs`) and live preview/execution binding (`execution/provider.rs`) consume this dispatcher.

The real installed Node 22.23.2 / npm 10.9.8 failed loading that script with `EISDIR: illegal operation on a directory, lstat 'C:'`. The collaborating C agent compared the same isolated environment and neutral cwd: ordinary script path succeeded; verbatim script path failed; verbatim Node executable with ordinary script path succeeded. Adding SystemDrive, restoring ProgramFiles and using inherited environment plus fixture overrides did not remove the failure. The CLI also failed outside the sandbox. Source inspection independently confirmed the offending argv was generated by the shared dispatcher.

Before-repair native evidence is retained under `dist/cleanup-home-final/native-cli-01/` and `native-cli-02/`, including `canonical-script.stderr.txt`, `system-drive.stderr.txt`, `runtime-program-files.stderr.txt` and `inherited-fixture-overrides.stderr.txt` in the latter directory. This was an actual provider compatibility defect, not merely a missing isolation variable or sandbox-only failure.

Existing CLI provider-authority tests copy `process_fixture` as the native Node interpreter; that fixture removes the first script argument instead of running Node's module loader. The old core shim test even expected the verbatim canonical argument. These tests correctly covered command/identity authority but did not establish real Node script loading.

## Fix and unchanged authority

- Added a private Windows Node argument conversion accepting disk and UNC filesystem prefixes. Relative paths and other device namespaces are refused. The runtime argument must be valid Unicode.
- Recanonicalize the converted argument and require exact equality with the canonical script before returning dispatch. A verbatim-only name that would resolve to a different normal file is refused.
- Keep the shim/script canonical paths and file digests in `support_files`; keep the native executable canonical path and hash. `ProviderBinding` still includes the runtime prefix arguments, support identities, executable hash, capability/version and configuration hash. The live binding check before dispatch is unchanged.
- Both supported shim and fixed Node entrypoint branches use the helper. Non-Windows argument behavior is unchanged. There is no shell, extra dependency, provider-version expansion or change to cleanup selection/confirmation.
- Updated existing core assertions to check runtime argument resolution against canonical identity rather than requiring the runtime string itself to have the verbatim prefix. Synced `.trellis/spec/backend/provider-authority.md` with this distinction and the need for actual Node acceptance.

Changed production file: `crates/devsweep-core/src/process/provider_dispatch.rs`. The only `execution/provider.rs` change is its existing test expectation and explicit canonical support identity assertion.

## Red/green regression evidence

Added `windows_shim_runtime_argument_preserves_the_canonical_script_identity` before the production repair. The original dispatcher failed its normal disk/UNC prefix assertion: **0 passed / 1 failed**. The assertion checks the actual emitted argument, not a synthetic formatted string.

After the repair, it passes and also verifies the runtime script recanonicalizes to the bound script, the native program stays canonical, and support paths/hashes remain exact. Additional Windows regressions cover Unicode/spaces, disk and UNC conversion, relative/device namespace refusal, and two real fixture files `entry.js.` / `entry.js` whose non-equivalent normalized identity must be rejected.

The first combined focused rerun caught an old mixed-slash string expectation in `fixed_node_entries_bind_script_and_use_native_interpreter`. That assertion was updated to compare resolved identity; its layout/shebang/native-interpreter checks remain intact. The final green run includes this test.
