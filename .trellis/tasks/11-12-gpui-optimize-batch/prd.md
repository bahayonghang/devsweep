# Optimize：批量维护计划与结果明细

父任务：[11-12-gpui-mole-parity-airy-glass](../11-12-gpui-mole-parity-airy-glass/prd.md)。差距编号 O1、O2 见父任务 `research/gap-analysis.md`。

## 目标

选好几项维护操作，审阅一次，确认一次，然后看到每一项是执行了、跳过了还是失败了以及原因。多操作计划先在 core 和 CLI 提供。

## 背景

目录有 19 项（`optimize/catalogue.rs:97-188`）：7 项可执行，3 项打开系统设置，8 项是指引，1 项只读观察。现在一份计划只能含一项（`optimize/plan.rs:156-165`）。

## 需求

| 编号 | 层 | 需求 | 差距 |
| --- | --- | --- | --- |
| R1 | core | 维护计划可含多个操作，整份计划一个实时预览摘要。只接受可执行类的操作。旧的单操作计划仍可读取和执行。 | O1 |
| R2 | CLI | `optimize plan --operation A --operation B`；`optimize preview` 与 `optimize run` 接受多操作计划；`run` 按顺序执行并逐项报告已执行、已跳过（原因）、失败（原因）。 | O1 |
| R3 | GPUI | 页面分两区：可执行的维护项（可勾选）和折叠的"指引与系统设置"。 | O2 |
| R4 | GPUI | 勾选后一次审阅、一个摘要、一次确认。运行中显示当前项，可在项与项之间取消。 | O1 |
| R5 | GPUI | 结果明细：每项的状态和原因。结果写入历史。 | O1 |

## 验收

- AC1（R1）：core 测试覆盖多操作计划的摘要绑定：改动操作集合或顺序后旧摘要失效；计划里出现非可执行类操作时被拒。
- AC2（R1）：旧版单操作计划文件仍能预览和执行。
- AC3（R2）：CLI 契约测试覆盖多个 `--operation`、逐项结果的 JSON、一项失败后其余项的处理（继续并如实报告）。没有摘要或没有 `--confirm` 时拒绝执行。
- AC4（R3）：指引与系统设置项不带复选框，不进入计划。
- AC5（R4、R5）：用测试执行器跑一份含成功、跳过、失败三种结果的计划，界面逐项显示，历史里有对应记录。
- AC6：需要提权的操作在未提权时显示为跳过并给出原因，不弹出提权。
- AC7：`just ci` 与 `just gpui` 通过。英文与中文原生截图。

## 不在范围

新增维护操作。改注册表、停服务。定时运行。把指引项变成可执行。
